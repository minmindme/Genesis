01 THE THESIS / 一个原语

万物先归于「一」，
再由规则分化出「万物」。

传统架构里，每新增一个业务就长出一张表。Genesis 反过来：让万物先归于一张同构表，再由元数据与角色规则分化出任何业务形态。

01 / ONE

一行原语

9 列，没有业务语义列。业务数据、元数据、边、历史、引擎指令、安全策略、命令、界面——全部是同一行。

Role ParentId

02 / TWO

两条轴

Role 定义「我是谁」，ParentId 定义「我在哪」。两条轴撑起图、树、文档、指令、历史——不需要第二张表。

03 / MANY

数据生成数据

表结构、路由、命令、UI、安全策略、历史都是行。插几行，系统自己长出来；改一行，行为随之改变。

BUG B1最阴险

UTF-8 无 BOM + 中文注释 + sqlcmd

表建完只有 8 列，TypeId 整列被静默吞掉。中文注释的字节错位，把列定义行并进了注释。

修复：UTF-8 with BOM。教训：编码不是细节，是会吞数据的基础设施。

BUG B10数量级

MemorySizeBits = 20，不是 20MB

FASTER 的内存预算写成了 2^20 = 1MB，装不下 6MB 数据，直接进入刷盘风暴，基准首轮卡死。

修复：2^25 = 32MB。教训：位宽参数没有「大概」，只有数量级。

BUG B381.1ms

AddWithValue 把 DateTime 推断成 datetime

历史行的时间戳被舍入到 3.33ms 精度，与原行差 1.1ms——审计时间线不再无损。

修复：显式 SqlDbType.DateTime2。教训：ORM 的「方便」经常以精度为代价。

E2 证据口径：数字来自 docs/UPDATE_LOG.md 与白皮书；基准不是 TPC-C，未覆盖多机/云网络；更新后的 CAS/历史热路径仍需 3.0 复测。这正是「可证伪」的意思。

05 THE JOURNEY / 26 轮

从一张表的初探，
到 system as history。

这不是一条「功能越加越多」的曲线。它更像一次持续 26 轮的自我打脸：每一次「理论上更快」，都被要求变成表格里的一行数字。

  1. 01–02

    一张表的初探

    单表 + 拆解/组装/路由，验证「对象 ↔ 行集合」往返成立。逐行写入只有 492 entities/s。

    先证明它能跑，再证明它值得跑。
  2. 03–04

    往返同化

    SqlBulkCopy + 子图预取：60,001 次往返 → 2 次。第 4 轮清空全表，引擎从空池自愈创世。

    「往返也是一种实体，图的整体搬运才是读写。」— 白皮书
  3. 05–06

    物理换装

    内存优化表 → 进程内 ConcurrentDictionary / FASTER。累计 148×，每实体 13.7µs。

    「计算便宜到可以忽略，I/O 才是价格。」— 白皮书
  4. 07–09

    引擎抽象

    IUniversalStore 让五引擎可插拔；SecuredStore 把 AES-GCM 与租户 AAD 包装进任意引擎。

    「改一行数据，换物理引擎。」— UPDATE_LOG
  5. 10–13

    同构扩张

    安全策略、快照/图双模、边同构依次落进池子。100K 双向边压测：磁盘 B+ 树遍历反超内存全扫 30×。

    「同构没有消灭索引的必要性，只是把索引的实现责任交还给了物理引擎。」— UPDATE_LOG
  6. 14–16

    壳子退场

    CLI 命令树、意图总线、Role=8 通用渲染器。一段 JSON 建出学生管理系统，前端零业务代码。

    「新增一种业务类型 = 往池子里插几行数据。」— 白皮书
  7. 17–19

    工业加固

    Token 鉴权、DataType 显式化、级联删除、实例级 GetData。外部评审指出三洞，开始从「演示级」走向「引擎级」。

    「别让 61 个绿灯，掩盖 3 个洞。」— 评审
  8. 20–26

    语义收口

    CAS + Role=6 历史 + 统一信封 + UpdateGraph 事务 + 语义规格。81 个测试，6 个基准门禁。下一步：QueryData。

    「system as data 的另一条腿，是 system as history。」— 评审 / 日志
